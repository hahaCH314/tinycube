## 1.5 【解決済み】フレームの絵の二重作成

`public/frames/heisei_*.svg` の3枚について、ヒマワリさんから回答がありました。

> **画像焼き込みのテスト用に仮置きしたダミーで、ボタンくんの10種とは無関係。
> 3枚とも削除し、`frames.ts` からも消した。**（2026-08-12）

→ **二重作成の心配は無くなりました。ボタンくんはフレームの絵に着手して大丈夫です。**

### ⚠️ あわせて、伝言の訂正

ボタンくんへ「`backdrop-filter` は録画に反映できないためゼロです」という報告が
渡っていますが、**因果が逆になっています**。正しくはこうです。

> **ボタンくんが10種を調査した結果、`backdrop-filter` は1つも使われていなかった。
> したがって焼き込みに支障はない。**

「ゼロ」は**調査結果**であって、制約ではありません。**ボタンくんが絵作りを
我慢する必要はない**、という意味です（もともと使っていなかった、というだけ）。

守るべき制約は元のまま1つ：**これから作る絵でも `backdrop-filter`
＝「後ろの映像が透けてぼやける」表現は使えない**（canvas に焼けないため）。
影・グラデ・角丸・内側の光・不透明なガラス風の質感は自由に使えます。

## 2. ボタンくん（v0）へ

### 先に読んでほしいもの

```
https://raw.githubusercontent.com/hahaCH314/tinycube/main/docs/tinycube-update-scope.md
https://raw.githubusercontent.com/hahaCH314/tinycube/main/docs/tinycube-ground-truth.md
```

とくに **scope の 0章**。「平成大プリクラ」と「渋谷デコラ」は**別のレイヤーの話**です。

- **平成大プリクラ＝体験。** プリクラ機と同じで、**先に枠を選んでから撮る**
- **渋谷デコラ × オタク文化＝見た目。** 色・装飾・質感

### お願いしたいこと

**(1) 新しい2画面のデザイン案**（これが一番欲しい）

まだデザインが1つも無い画面です。

- **同意画面**：全画面。見出し「はじめに」＋本文＋「同意してはじめる」ボタン1つ。
  本文は scope 1章の原文をそのまま使ってください（**書き直さないでください**）。
  改行も原文のまま
- **設定画面**：フレームを選ぶのが主役。利き手（右／左）のトグルと、
  下に「この設定で撮る！」ボタン。**プリクラ機の「枠を選ぶ画面」の気分**で

**(2) フレームのデザイン ← 本命**

`backdrop-filter` の調査ありがとう。**10種ともゼロ**とのことなので、
**焼き込みは問題なく進められます。** 懸念は消えました。

CSS の10種を、canvas で描ける形（9スライス、`--pink` / `--cyan` / `--violet` /
`--lemon` 準拠）の仕様に翻訳してください。**ただし 1.5節の確認が済んでから。**

**サムネイル（プラン2）は、別納品にしないでください。**
各フレームを SVG＋数値で定義するなら、**そのサムネはその SVG を小さく描けば済みます**。
別に作ると「録画に焼く絵」と「タイルに出す絵」が別々に定義され、
片方だけ更新される日が来ます。**1つの定義から両方を出す形**でお願いします。

（`.frame-tile` / `.frame-item` は器だけあって中身が無い、という指摘は正しいです。
ここはボタンくんの出しどころです）

### 守ってほしいこと

- **出力をリポジトリに直接置かないでください。** 伊波さん経由で渡してください。
  素性の分からないファイルが増えると、次に見た人が消していいか判断できません
- **撮影画面の中央（映像が映るところ）には何も置かないでください。** 録画そのものです

## 3. ヒマワリさんへ

優先順にお願いします。**1 が終わるまで、シオンは動けません。**

### (1) 最優先：同意画面と設定画面を `App.tsx` に実装する

- クラス名は scope 3章の設計案どおりに。**シオンはその名前で CSS を書き終えています**
- **同意画面の本文は scope 1章の原文をそのまま。** 要約も言い換えもしないでください。
  `white-space: pre-line` を当ててあるので、**`<br>` を入れずに文字列をそのまま渡せば
  改行が保たれます**
- **画面の出し分けは条件レンダリング**（出さないときは DOM に置かない）でお願いします。
  CSS のクラスで `display: none` を当てる方式だと、スキン側の `display: flex` と
  打ち消し合います
- **録画ロジックには触らない**（`App.tsx` の外側でのフラグ管理、という当初方針のまま）

**終わったら教えてください。** シオンが本番で実測して、クラス名一覧を
ground-truth に反映し、新画面のスキンを検証します。

### (2) 9スライスの合成を、実際に動かして確認する

実装済みと聞いていますが、**コミットもデプロイもされていないので、
まだ誰も動いているところを見ていません**。

- 縦向きで1回、**横向きに切り替えてもう1回**録画して、
  **枠の角が歪んでいないか**を見てください。9スライスはそこを守るための作りです
- 確認できたらコミットして、手紙に「確認した」と書いてください

### (3) 素性の分からないファイルの扱いを決める

- `src/RoundBlueButton.tsx` … v0 取り込みテスト用でしたよね。もう不要なら消す
- `public/frames/heisei_gyaru.svg` / `heisei_rakugaki.svg` / `heisei_split4.svg`
  … これは何のために置いたものですか。使うなら**手紙に用途を書いてからコミット**、
  使わないなら消す

**ルール**：v0 の出力をそのまま置かない。置くなら用途を手紙に書いてからコミットする。

### (4) その後

- 利き手トグルの繋ぎ込み
- 即保存 UX（録画後にプレビューを挟まず即保存）
- **スキン CSS の `src/index.css` への取り込みは、シオンの検証が終わってから**
