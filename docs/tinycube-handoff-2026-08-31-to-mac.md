  撮影は入口で、**プリクラ帳（貯めて見返す体験）が core**という位置づけです
- **撮影画面のフレームを主役に。** 枠が 3px の細い縁取りで、グレーの
  「CAMERA VIEW」の方が目立っていました。ピンク→パープル→シアンの

⚠️ `.preview-stage` / `.stage-canvas` は**触っていません**（聖域のまま）。

## 3. カメラの見え方（`src/App.tsx`）

伊波さん「camera 少しだけブラックも white も強くできる？」→「強めにではなくね」
→ **「ユーザーがほうれい線は消してくれと」**。

⚠️ **コントラストは上げていません。** 上げると影が濃くなって、ほうれい線や
クマがくっきり出ます（求められているのは逆）。代わりに:

```
  brightness  真ん中から上へ 8%   影を浅くする
  saturation  真ん中から上へ 10%  色を少し濃くする
```

これがプリクラの定番の見え方（肌を飛ばして色は濃く）です。

⚠️ **描いたあとで触っていません。** `recorder.ts` の長い注意書きどおり、
`g.filter` は重く、`globalCompositeOperation` は真っ暗になりました。
今回は `getUserMedia` の直後に **`applyConstraints` を1回呼ぶだけ**で、
描画は素のままです。効かない端末では黙って無視されます（try/catch 済み、
失敗しても映像は流れる）。

**⚠️ ここは実機でしか確かめられません。** そちらで iOS を触るときに見てください。

## 4. プリシートのコマの形（`src/sheet.ts`）

伊波さんが型えらびの見本を見て「この形はありだけど、**このサイズはうちの写真ではない**」。

調べたところ、**うちの写真は縦長（9:16 ＝ 横÷縦でおよそ 0.56）**なのに、
横長のコマがたくさんありました。`buildSheet` は「コマにぴったり収める
（はみ出しは切る）」ので、**上下が大きく削られて顔が切れます。**

実測では `7a` が7コマ中6コマ、`7b` には比 **3.91** の極端に平たいコマがありました。

**10型50コマ全部を作り直して、すべて 0.5〜1.3 に収めました。**

```
3a  1.28  0.80  0.80
3b  0.61  0.74  0.74
4a  0.71  0.87  0.87  1.17
4b  0.75  0.61  0.66  0.81
5a  0.76  1.02  1.02  0.80  0.80
5b  0.76  0.80  0.80  1.02  1.02
6a  1.07 ×6
6b  0.62  0.78  0.78  0.78  0.76  0.76
7a  1.00  1.24  1.24  0.84  0.84  0.84  1.28
7b  1.14  1.12  1.12  0.84  0.84  0.84  1.29
                              → 50コマ中 0 コマが範囲の外
```

⚠️ **紙に余白が出るのは構わない**（伊波さん「空白有で」「写真がきれいに
収まれば余白は仕方ない」）。隙間なく埋めようとすると、必ずどこかのコマを
横へ伸ばすことになり、結局そこで顔が切れます。**比を優先して余白は残す。**

そもそも、できあがりをインスタに上げる時点で余白は避けられません
（紙は 1:1.44、インスタに載る縦は 4:5 まで。`toInstaSheet` が
「切らずに 4:5 の紙の真ん中へ置く」ので左右に白が出る）。仕組み上そうなるものです。

### 検証の道具を足しました

```sh
node tools/_sheetratio.mjs    # 全型のコマの比と枚数を測る。範囲外は ! が付く
```

⚠️ 型を足したり直したりしたら、**必ずこれを走らせてください。**
（正規表現で cells を数えると、コメント行が混ざって数を読み違えます。
この道具は式ごと評価して実際の値を読むようにしてあります）

## 7. 監査をかけて、9件直しました

出す前に別のエージェントに監査させたところ、**自分では気づけなかった不具合が
9件**見つかりました。全部直してあります。同じ轍を踏まないよう、原因ごと残します。

### 読めなくなっていた文字（4件）

⚠️ **地を「黒」から「生成り」に変えたら、暗い地の前提で書かれた字は全部
読めなくなる。** 渋谷スキンは黒地だったので、薄い色や `var(--cyan)` の
ままで良かったものが、生成りの上では消えます。

| どこ | 前 | いま |
|---|---|---|
| **¥300 の売り文句**（`.unlock-points li`） | **1.02:1（ほぼ見えない）** | 18.51:1 |
| 設定の見出し（`.opt-label`「動き」「色み」） | 1.12:1 | 直した |
| 横向きの案内（`.sheet-note`） | 1.66:1 | 直した |
| マイフレーム追加（`.frame-tile.add`） | 2.06:1 | 直した |

⚠️ 特に1つめ。`setup.css:109` が **`.unlock-points li`（子）** に
直接 `color:#fff` を当てているので、親の `.unlock-points` を塗っても勝てません。
**買ってもらうための2行が、白地に白で消えていました。**

### 見た目の崩れ（2件）

- **「はじめに」の縦書き見出しが、メモ帳の下に隠れていた。** 320〜412px の
  どの幅でも 25px ほど食い込み。縦書きは右から始まるので、隠れるのは
  **1文字目の「に」**。メモ帳の幅を「見出しのぶんを引く」形にしました
- **下の斜めブラシストロークが、ボタンの中の小さな楔になっていた。**
  ボタンの擬似要素にしていたのが原因で、(1) ボタンの `transform` が
  `position: fixed` の基準を奪い、(2) `clip-path` がはみ出しを切っていました。
  `.manner-content::after` へ移して直しました

### アイコン（2件）

⚠️ **新しいロゴは「白い紙に貼ったシール」の絵で、周りの余白ごと焼いていました。**
その結果 `ic_launcher` が **RGBA → RGB（透明が消滅）** し、ホーム画面が
**白い四角の中の小さいロゴ**に。`ic_launcher_round` は端末が丸く抜く前提なので、
角が不透明だと丸くなりません。

→ 余白を測って **viewBox を絵の実寸に切り**、縁いっぱいまで使うようにしました。
測る道具も置いてあります。

```sh
node tools/_logobox.mjs          # 元絵の余白を測る。出た viewBox を favicon.svg へ
```

⚠️ もう1件。**`public/favicon.svg` が 2.3MB に膨れていました**（PNG を
base64 で埋めたため。JS 本体 306KB の 7.8 倍）。絵は `public/logo-src.png`
に置いて `href` で指す形にし、**296 バイト**になりました。
`tools/icons.mjs` は焼くときだけ data URI に差し替えます。

`index.html` のキャッシュの番号（`?v=`）も 20260813 → 20260831 に上げました。
上げないと、前から使っている人には**古いアイコンが出たまま**になります。

### 押せなくなっていたボタン（1件）

**「ぜんぶ使えるようにする（¥300）」が 320px / 360px で画面からはみ出していました。**
主役の3枚と同じ 132px にしていたので、4枚積むと入りきらず。
買う導線なので、ここは低く（92px）しました。ここは「プリクラ帳より
目立たせない」場所でもあるので、低くて構いません。

### カメラの直し（監査の指摘で作り直し）

3つ間違っていました。

1. **`await` が `setCamOn(true)` の前にあった。** `try/catch` は
   「返ってこない promise」を助けられません。固まる端末では
   **撮影画面がいつまでも出ない**ことになります → 後ろへ移動
2. **「知らない制約は黙って無視される」は嘘でした。** 実測すると
   `OverconstrainedError` を投げ、しかも `advanced` 全体が巻き添えで落ちます
   → brightness と saturation を**1つずつ**試す形に
3. **`step`（刻み）を見ていなかった。** 刻みを外れた値は弾かれるので、
   効かない端末で黙って何も起きません → 刻みに乗せてから渡すように
