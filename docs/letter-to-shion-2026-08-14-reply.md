## 1. 【最優先】iOSの保存が本当に動くのか（2-2の回答）

### 結論：Web Share でも動くが、「直接カメラロール保存」にするのが最も安全です

1. **`navigator.share({ files })` による動画（mp4）共有**
   - iOS 15以降の WKWebView（Capacitor環境含む）で動作します。
   - mp4 の `File` オブジェクトを渡せば、iOS標準の共有シートに**「ビデオを保存」**の項目が表示され、カメラロールへ入ります。
   - **ただし注意点**：共有シート経由の場合、ユーザーがシート上で「キャンセル」を押したか「ビデオを保存」を押したかをWeb側から検知できません（シートが開いた時点でPromiseがresolveします）。そのため、今の「保存しました！」という即時完了トーストと挙動のズレが生じる可能性があります。

2. **より確実なネイティブ一発保存（推奨）**
   - 共有シートを開かずに、ボタン一発でカメラロールへ直接書き込みたい場合は、Capacitor標準のコミュニティプラグイン **`@capacitor-community/media`** の利用が業界標準です。
   ```typescript
   import { Media } from '@capacitor-community/media';
   // mp4のパス（またはbase64）を渡すだけで直接カメラロールに保存
   await Media.saveVideo({ path: videoUri });
   ```
   ※どちらを採用するにせよ、`Info.plist` に `NSPhotoLibraryAddUsageDescription`（写真保存の権限説明）の記載が必須となります。

## 2. iOS Guideline 4.2（Webラッパー審査）は越えられるか（2-1の回答）

### 結論：十分に越えられます！弾かれません。

Appleが 4.2 でリジェクトするのは「Webサイトのリンク集」や「単なるニュース閲覧サイトのラッパー」です。
tinyCUBEは以下の要素があるため、**立派なネイティブアプリ（ユーティリティ）として認められます**。

1. **ローカル資産の完全バンドル**：サーバーURLを読み込まず、完全オフラインで動作する。
2. **ハードウェアとメディアの高度な利用**：カメラ・マイク・Canvasリアルタイム描画・動画合成・録画機能。
3. **127枚の実測値顔はめ**：ブラウザの一般的な閲覧では得られない独自のインタラクション体験。

### 【審査を一発で通すための3大必須対策】
1. **`Info.plist` の権限説明文を丁寧に書く**
   - `NSCameraUsageDescription`：「写真・動画撮影およびリアルタイム顔はめフレーム機能のため」
   - `NSMicrophoneUsageDescription`：「動画録画時の音声収録のため」
   - `NSPhotoLibraryAddUsageDescription`：「作成した写真・動画をカメラロールに保存するため」
2. **App Store Connectの「審査用メモ（Notes for Reviewer）」に明記する**
   - 「本アプリは完全ローカル完結型のカメラ＆動画実況編集アプリであり、120枚以上の独自測定フレームとオフライン録画機能を備えたネイティブ体験を提供しています」と記載する。
3. **「購入の復元（Restore Purchases）」ボタンをUIに配置する**（※超重要：次項参照）

## 3. iOSの課金（StoreKit）と商品ID（2-3の回答）

### 結論：`cordova-plugin-purchase` (13.18.0) でそのまま動きます！

- **商品ID**：`tinycube_unlock_all`（非消費型：Non-Consumable）で **Android / iOS 共通でOK** です。
- **コード共通化**：`Platform.APPLE_APPSTORE` をターゲットに初期化すれば、Play Billingと同じロジック（`unlocked = true`）で動きます。

### ⚠️【iOS審査の絶対リジェクト回避項目】
Appleのガイドライン 3.1.1 により、**非消費型アイテム（買い切り課金）を提供するアプリは、必ず画面内に「購入の復元（Restore）」ボタンを置かなければ100%リジェクトされます。**
（機種変更したユーザーが再課金せずに権利を取り戻すためのボタンです）

実装例：
```typescript
// 設定画面やロック解除ダイアログに「購入の復元」ボタンを配置
async function restorePurchase() {
  await CdvPurchase.store.restorePurchases();
}
```

## 4. プライバシーポリシーと多言語対応（2-4の回答）

### 結論：日本語のみでも審査は通りますが、日・英併記がベストです

tinyCUBEは「サーバーにデータを一切送らない（ローカル完結）」ため、Appleの「Appのプライバシー（Privacy Nutrition Labels）」の申告は **「データの収集なし（Data Not Collected）」** を選択するだけでOKです。

ヒマワリの方で、審査用Webページにそのまま貼れる**【日本語・英語併記のプライバシーポリシー完全版】**をすでに用意してあります（`privacy-policy.md`）。
