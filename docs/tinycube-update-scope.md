## 0. まず — 2つの言葉は、別々の話

「平成大プリクラ」と「渋谷デコラ」は、**どちらかを選ぶものではありません。
指しているレイヤーが違います。** 片方だけを見て作ると、必ずズレます。

### 平成大プリクラ ＝ **体験（フロー）の設計思想**

**プリクラ機と同じ順番にする。つまり「先に枠を選んでから撮る」。**

だから起動フローが「同意 → **設定（フレーム選択）** → 撮影」に変わるのは、
UX の都合や画面追加の話ではなく、**この製品の芯**です。

→ **設定画面のフレーム選択は、削ったり後回しにしたり、
撮影画面の中のシートに畳んだりしない。** 迷ったらここに戻る。

### 渋谷デコラティブストリート × オタク文化 ＝ **見た目（ビジュアル言語）**

配色、装飾、素材感、フォントの雰囲気。UI の見た目だけの話。
`tinycube-skin-shibuya.css` はこちらを担当している。

### 使い分け

| 判断すること | どちらを見るか |
|---|---|
| 画面の順番、何を先に選ばせるか、何を出さないか | 平成大プリクラ（体験） |
| 色、装飾、質感、アニメーション | 渋谷デコラ × オタク文化（見た目） |

v0 へのプロンプトを書くときも、**この2つを分けて書く**こと。
混ぜると「見た目は合ってるがフローが違う」ものが出てきます。

### 各項目の中身

**1. 起動フロー**
アプリを開いた最初に全画面のマナー喚起（同意）画面。「同意する」で次へ。
次に設定画面（フレーム選択＋利き手）。選んだら撮影画面へ。

#### 同意画面の文面（伊波さんの原文。2026-08-12 改稿）

> **⚠️ この文面は要約したり、言い回しを整えたり、AI が書き直したりしないこと。**
> 変えるときは伊波さんに確認してから、このファイルを上書きする。

見出し：**はじめに**

```
このアプリケーションは
みなさんの日常を切り取る
動画＆写真撮影アプリです
SNSへの投稿等及び、二次使用は
自由に行えます
みなさんの愛のあるご利用を
お願いすると共に
このアプリが誹謗中傷への
誰かを傷つける道具と
なりませんよう
お願い申し上げます
```

**改行は意図的なもの**なので、そのまま出す。CSS 側（`.manner-text`）に
`white-space: pre-line` を当ててあるので、**`<br>` を入れなくても、
上の文字列をそのまま渡せば改行が保たれます**。

**実装は `App.tsx` の外側でのフラグ管理で行う。録画ロジックには触らない。**

⚠️ この順番は 0章の「平成大プリクラ＝先に枠を選んでから撮る」から来ています。
**「起動が遅くなるから」「タップ数が増えるから」を理由に、フレーム選択を撮影画面の
中に移したり、スキップ可能にしたりしない。** そうすると製品の芯が消えます。

**4. 即保存 UX**
「無駄なシェア画面などは一切出さず、デバイスに即保存されて完了」で確定済み。
シェア画面・プレビュー画面を**足さない**。

**5. フレームの焼き込み**
CSS で描いた枠は canvas に合成できないため、アセット（SVG / PNG / canvas 直描き）に
変換が必要。合成関数は**9スライス（角は等倍、辺だけ伸縮）前提**。縦横を切り替えたときに
角が歪むのを防ぐため。`recorder.ts` の `drawFrame` に実装済みと申告されているが、
**まだコミットもデプロイもされておらず、動作は誰も確認していない**。

⚠️ **`backdrop-filter`（枠の後ろの映像をぼかす）は、PNG でも SVG でも再現できません。**
canvas に直接描いたときだけ可能。v0 のデザインがこれに依存していないか要確認。

## 2. やらないこと（範囲外）

**頼まれていないものを足さない**ための線引き。ここに書いてあることをやりたくなったら、
まず伊波さんに聞く。

- **録画の中央（`.preview-stage` / `.stage-canvas`）を飾らない。** 動くもの・光るもの・
  枠を被せない。ここは録画そのもの。絶対不可侵
- **シェア画面・プレビュー画面を足さない**（1章の4で「出さない」と確定済み）
- **通信先を増やさない。** 製品LPに「通信するのは Web フォント取得と起動時の更新確認の
  2つだけ」と明記してある。増やすなら**先に LP を直さないと嘘になる**
- **シオンは `src/` に書き込まない。** 納品は `docs/` にスキン CSS と手紙
- **v0 の出力をそのままリポジトリに置かない**（4章）

## 3. いま止まっているところ

**シオンの作業（項目7）が、ヒマワリの実装待ちでブロックされています。**

理由：スキン CSS は既存スタイルシートの**丸ごと置き換え**なので、**そこに無いクラスは
素の HTML の見た目になります**。新画面のクラスが CSS に1行も無いまま画面を出すと、
同意画面と設定画面だけ無装飾で表示されます。

ヒマワリから届いているクラス名設計案（この通りに実装されるなら、シオンが先回りできる）：

```html
<!-- マナー喚起（同意）画面 -->
<div class="manner-screen">
  <div class="manner-content">
    <h2 class="manner-title"></h2>
    <p class="manner-text"></p>
    <button class="manner-agree-btn"></button>
  </div>
</div>

<!-- フレーム・利き手選択（設定）画面 -->
<div class="setup-screen">
  <div class="setup-header"><h2 class="setup-title"></h2></div>
  <div class="setup-content">
    <div class="hand-setting">
      <label><input type="radio" name="hand" value="right" checked> 右</label>
      <label><input type="radio" name="hand" value="left"> 左</label>
    </div>
    <div class="frame-grid">
      <button class="frame-item frame-item-active"></button>
      <button class="frame-item"></button>
    </div>
  </div>
  <div class="setup-footer"><button class="start-btn"></button></div>
</div>
```

### フレーム選択の命名は `.frame-picker` / `.frame-tile` / `.on` に寄せます

伊波さんの「どっちでもいい」を受けて、**既存側に統一**しました。理由：

- このアプリはアクティブ状態を**すべて `.on`** で表している
  （`effect-btn.on` / `shape-switch button.on` / `pause-btn-round.on` / `frame-tile.on`）。
  `.frame-item-active` だけ別の書き方になると、次に触る人が迷う
- 既存の CSS がそのまま使えるので、新しく書く量も減る

**保険**：`.frame-grid` / `.frame-item` / `.frame-item-active` にも同じ見た目を当てて
あります。実装がそちらの名前になっても無装飾にはなりません。命名が片方に統一できたら、
CSS 側のその保険ブロックは消してかまいません。

### スキン CSS への追加は済んでいます（ただし実機未検証）

`tinycube-skin-shibuya.css` に 16章「起動フローの2画面」を追加しました。
上の設計案どおりのクラス名で書いてあります。

⚠️ **この2画面はまだ本番に存在しないので、実機で見た人は誰もいません。**
既存画面に副作用が出ていないことだけは確認済み（`docs/shoot.cjs` で再測定、
390×844 と 844×390 で全項目 PASS、クリック可否も全部通過）。
**実装が乗ったら、必ず `shoot.cjs` で測り直してください。**

### ⚠️ 実装時のお願い：画面の出し分けは条件レンダリングで

`.manner-screen` / `.setup-screen` には `display: flex` を当てています。
**CSS のクラスで隠す方式（`display: none` を後から当てる）だと打ち消し合う**ので、
**出さないときは DOM に存在させない**（React の条件レンダリング）でお願いします。

## 5. 順番（依存関係）

```
ヒマワリ：新画面を実装して、DOM を確定させる
      ↓
シオン：本番に当てて実測 → クラス名一覧を ground-truth に反映
      ↓
シオン：新画面ぶんのスキン CSS を追加 → 実機検証
      ↓
ヒマワリ：スキンを src/index.css に取り込む
```

デザイン（v0）はこの流れと並行して進められますが、**出てきたものは必ず
ヒマワリが実装として取り込む**。リポジトリに直接置かない。

焼き込み（項目5）はこの流れと独立して進められます。
**アセットが SVG でも PNG でも canvas 直描きでも、合成パイプラインは共通**なので、
形式が決まる前に着手して問題ありません。
