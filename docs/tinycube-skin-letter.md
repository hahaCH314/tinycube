やったこと：Electron で **https://tinycube.vercel.app/ の本番ビルドを実際に開き、

結果、**縦向き4サイズと横向き、すべて機械チェックは通っています**：

## 1. 実機で見つかって直した、重大なもの3つ

### (a) 全ボタンが押せなくなるところだった

`.ui-layer` に `pointer-events: none` を掛けていました。ところが実物では
**ヘッダーも下バーもレールも、全部 `.ui-layer` の中にいる**。私は
`.app-container` の直下に縦並びだと思い込んで書いていたので、そのまま当てたら
**画面上のボタンが1つも押せない**状態でした。

`.ui-layer` の中の `button` / `a` / `input` と3つのバーに `pointer-events: auto`
を戻して解決。上のクリック可否テストは、この再発を防ぐために入れています。

### (b) 位置指定を実構造に合わせて全面的に書き直した

実物の構造はこうでした（実測）：

```
.app-container
  main.preview-stage  > input, .stage-box, .video-placeholder
  div.ui-layer        > .city-frame.top/.bottom, .header, .bottom-controls, .side-panel.left/.right
```

`.ui-layer` が全画面のオーバーレイで、そこに全部の UI が乗っている。
これに合わせて `.header` / `.bottom-controls` を `position: absolute` にし、
`.preview-stage` も含めて `--chrome-top` / `--chrome-bot` / `--gutter` の3変数から
位置を出す形に統一しました。

### (c) レールの高さ計算がボーダー2px ぶんずれていた

`.side-panel` の上下ボーダー 2px を引き忘れていて、**左レールが全サイズで2px はみ出し、
15個目だけスクロールしないと押せない**状態でした。修正済み。

さらに実物のレールは、想定より子要素が多い場面があります。そこで `.effect-btn` を
`flex: 0 1 var(--btn-h)`（＝計算値を基準にしつつ、詰まったら縮む）に変更しました。
**`--rail-max` を変えれば基準が変わる**という設計はそのままです。

## 2. 横向きだけ、作りを変えました

横向き（844×390）では、**レールが1列では物理的に足りません**。
実測でレールの高さは 270px しか取れず、15個 × 最低20px = 328px には届かない。

そこで **横向きのときだけレールを2列（8段 × 2列 = 16枠）** にしました。
`@media (orientation: landscape) and (max-height: 500px)` の中だけの変更です。
これで横向きでもボタンは 30.25px あり、全部見えてスクロールも出ません。

### ⚠️ ヒマワリさんに1つ調べてほしいこと

横向きで `.side-panel` の `top` / `bottom` に **`!important` を付けても効きません**
（計算値が `top: 48px / bottom: 72px` に固定される）。インラインスタイルでもなく、
私の CSS 以外のスタイルシートも読み込まれていない状態で再現します。
同じルールの中の `width` は効いているので、`top` / `bottom` だけが何かに
押さえられている。**原因は突き止められませんでした。**

2列化で実害は消えているので急ぎではありませんが、アプリ側で
レールの位置を制御している箇所に心当たりがあれば教えてください。

## 3. 伊波さんに決めてほしいこと

**アプリは `.stage-box` の大きさを JS で自分で決めています**（9:16 で画面いっぱい）。
CSS で余白を作っても効きません。つまり **UI は必ず映像の上に重なる**、というのが
このアプリ本来の設計です。

その前提だと、ヘッダー・下バー・レールの中で流している**デコラのアニメーション
（斜めのリボンやテープ）も、映像の上に乗ります**。各バーの `overflow: hidden` の
内側には閉じ込めてありますが、「録画画面の上で何かが動く」ことに変わりはない。

- 今のまま（にぎやかさ優先）
- バーの中のアニメーションだけ止めて、静かなすりガラスにする（`::before` を消すだけ）

どちらでも1行で切り替わります。好みを教えてください。

## 4. ボタンくんへ — フレームの件

別件で「フレームも録画に焼き込めないと意味がない」という話が出ています。

**CSS で描いた枠は、そのままでは動画に焼き込めません。** 録画は canvas を録って
いるので、DOM は合成対象になりません。とくに **`backdrop-filter`（枠の後ろの映像を
ぼかす）だけは、PNG に書き出しても SVG に作り直しても再現できません。**

- グラスモーフィズムのフレームで、**「後ろの映像をぼかす」表現に依存している部分**が
  あれば教えてください。そこだけ別扱いが要ります
- 影・グラデ・角丸・内側の光は canvas でも SVG でも再現できます。心配いりません

このスキン CSS の `backdrop-filter` は **UI（ヘッダー・レール・シート）にしか
使っていない**ので、録画には一切影響しません。切り分けてあります。
