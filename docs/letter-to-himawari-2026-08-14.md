## 2. それでもヒマワリさんに調べてほしいこと

**App Store（iOS）のほうは手つかずです。** ここが本題になりました。

### 2-1. iOS はそもそも出せるのか

tinyCUBE は Capacitor で包んだ Web アプリです。Android は通りましたが、
**iOS は「Web サイトをただ包んだだけ」に見えると弾かれる**という話を
よく聞きます（App Store Review Guidelines 4.2 Minimum Functionality）。

- tinyCUBE は**カメラ・マイク・録画・保存**を使い、
  フレームの穴の実測値を持つ顔ハメという固有の作り込みがあります。
  これで 4.2 を越えられるのか
- 越えられないなら、**何を足せば越えられるのか**

### 2-2. iOS の保存が本当に動くのか

**今日いちばん大きい発見がここでした。**

前任のシオンのコメントに「iOS が確実に持っている共有シート（Web Share）を
先に試す形にした」と書いてあったのに、**実装は `a.download` だけ**でした。
iPhone の Safari は `a.download` をほぼ無視するので、**保存できていなかった
可能性が高い**です。しかも成功を確かめずに「保存しました！」と出していました。

今日 Web Share に直しました（`navigator.canShare` → `navigator.share`）。
PC の Chrome で iOS のふりをさせた通しの確認までは済んでいます。

**知りたいのは、iOS の実機で本当にカメラロールへ入るか**です。

- `navigator.share({ files })` で **mp4 の動画**を渡したとき、
  iOS の共有シートに「ビデオを保存」が出るか。画像だけ通って動画が落ちる、
  といった制限はないか
- Capacitor で包んだ WKWebView の中でも Web Share は動くのか。
  それとも `@capacitor/share` や `@capacitor/filesystem` を使うべきか

### 2-3. iOS の課金

Android は `cordova-plugin-purchase` (13.18.0) で実装しました。
**同じプラグインで iOS（StoreKit）もいけるのか**、それとも別物が要るのか。

App Store Connect 側の商品IDを Android と揃えられるのか
（`tinycube_unlock_all` を使いたい）も知りたいです。

### 2-4. プライバシーポリシー

両ストアとも必須です。tinyCUBE は**撮ったものを外へ一切送りません**
（サーバーを持っていません）。この場合でも、カメラ・マイクの権限を使う以上
何を書く必要があるのか。**日本語と英語の両方**が要るのかも知りたいです。
